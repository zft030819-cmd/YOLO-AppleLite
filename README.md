# YOLO-AppleLite — public code and deployment package

This package contains source code, training configurations, final annotations and deployable NCNN models. Historical training logs, measured accuracy, per-image timings, research-result tables, validation reports and PyTorch checkpoints are not distributed here.

## Environment

Reference training environment: Python 3.10, PyTorch 2.2.2, torchvision 0.17.2. Install the appropriate PyTorch build for your platform, then `pip install -r requirements.txt` and `pip install -e . --no-deps`. Use this repository's local Ultralytics implementation. The requirements are not a complete historical environment lockfile.

## Restore data

Obtain original image pixels from the [Roboflow source](https://universe.roboflow.com/south-china-agricultural-univercity/apple-leaf-5rlik/dataset/1). Images are not redistributed. See `data/DATA_NOTICE.txt` for attribution and source terms. Final processed labels, the fixed split and hashes are included.

```bash
python scripts/restore_data.py --images-root /path/to/download --check-only
python scripts/restore_data.py --images-root /path/to/download --output /path/to/new_dataset
```

Restoration does not modify the downloaded originals and stops on hash mismatch. Final split: 5,870 training, 356 validation and 356 test images.

## Train and evaluate

```bash
python train.py --data /path/to/new_dataset/data.yaml --model applelite --loss nwd
python scripts/evaluate_paper.py --weights /path/to/your_checkpoint.pt --data /path/to/new_dataset/data.yaml --split val --device cpu --output runs/new_evaluation
```

Checkpoints are supplied by the user or generated by training. They are not included in this public package. `evaluate.py` computes separate COCO area-aware metrics; do not interchange them with Ultralytics AP. Results created by these commands stay local and are git-ignored.

## Deploy

The interactive application is in `raspberry_pi/`. On 64-bit Raspberry Pi OS, run `bash install.sh` and `bash start.sh` from that directory. NCNN 320/640 FP32 models are included.

Two controlled benchmark configurations are also provided:

- `deployment/pair640/`: native-EMA 640 FP32 baseline and AppleLite.
- `deployment/six_experiments/`: 640/512/416 FP32 and mixed INT8, with unrolled EMA.

```bash
python scripts/materialize_benchmark_images.py --data-root /path/to/new_dataset
cd deployment/six_experiments
PYTHON=/path/to/pi_environment/bin/python bash run.sh
```

Benchmarks create new local timing outputs. They do not require or contain historical accuracy files, and they no longer attach paper accuracy values to timing tables. Use `scripts/evaluate_deployment.py` to compute new deployment accuracy separately. The two conversion families use different EMA exports and must not be combined to claim conversion speedups.

`python scripts/export_ncnn.py --help` describes native FP32 and training-only mixed INT8 export. Supply your own checkpoint and matching PNNX/NCNN tool executables. The fixed calibration image identities are included.
